# Review — 2026-10-02

This is a review of `kind` right after the symb → kind rename (branch `rename-to-kind`). It covers
(a) inconsistencies in code and text, (b) complexity, (c) security and (d) tests. Every finding was
fixed in this round unless its status says otherwise.

How it was checked:
- live probes against `master` and against the branch;
- three independent review passes;
- the full test suite with warnings as errors;
- security proofs of concept against a wheel installed into a fresh venv outside the repo.

Status values:
- **fixed (A/B/C):** fixed in one of the three commits that close this round —
  **A** library, tests and dependencies; **B** tooling; **C** docs.
- **by design:** a decision that stays and is documented.
- **open:** a recommendation not acted on.

## (c) Security

| sev | finding | status |
|---|---|---|
| high | Loading a schedule file imported and ran any function it named (`os.system`); the CLI built a scheduler (and so loaded the file) for every command. | **fixed (A)**: one `resolve_callable` with an allowlist (`Scheduler(allowed_modules=…)`, CLI `--allow-module`); empty by default |
| high | `register_mixin` called `eval()` on string values. | **fixed (A)**: strings raise `TypeError` |
| med | Mixins could replace core attributes silently (`safe=False` by default; the static/property branches skipped even that check). | **fixed (A)**: `safe=True` default; private/dunder names always refused; core names are checked across the class hierarchy |
| med | `freeze()` was one global flag that did not stop graph edits; `immute()` on one Kind froze mixins for the whole process. | **fixed (A)**: per-instance freeze guarding attributes, edges, relations, delete and maturing; the process-wide registry lock is `lock_mixins()` |
| med | `to_json/yaml/toml` serialized the entire process pool. | **fixed (A)**: only the Kind's connected component |
| med | Parsing a file merges into existing Kinds of the same name. | **by design** (interning); documented in `kind_vs_type.md` and pinned by a test |
| med | Unbounded memory: the creation-order tree held strong references, so the weak pool never shrank; `hasattr(k, …)` created Kinds. | **fixed (A)**: weak tree nodes, purged on write; private probes raise |
| med | `footprint`, `to_mmd` and DOT rendering recursed; cycles (`footprint`) or 3 000-deep chains crashed. | **fixed (A)**: iterative walks; tests on 5 000-deep cyclic graphs |
| low–med | DOT injection: names were quoted without escaping. | **fixed (A)**: `\` and `"` escaped |
| low | Scheduler awaited jobs while holding its lock (a job adding a job deadlocked); the CLI `run` busy-looped and never started the loop. | **fixed (A)** |
| med | Publishing used a stored PyPI password; actions unpinned; no lint. | **fixed (B)**: Trusted Publishing, actions pinned by SHA, `permissions: contents: read`, pyflakes in CI. **User step:** add the trusted publisher on pypi.org |

## (a) Inconsistencies

**Code that did not do what it said:**
- `first/last/len/seek/each` called methods the AVL tree did not have.
- `next()` inserted twice.
- `tree()` passed a non-existent argument.
- `delete()` iterated an unset slot.
- `insert()` wrote its cursor into an elevated attribute.
- `a_process_batch` awaited `None`.
- `GraphTraversal.family_mode` was cosmetic (all neighbours were sorted together).
- `time_dim` defined 20 methods twice; the second copy silently replaced the first, which also lost `filter_by_weekday(n)`.
- **Status: fixed (A).**

**Kind-specific defaults:**
- `Kind()` set `origin` to a class-path string.
- The first origin given was ignored.
- `ref` could not be set.
- Containers merged across conversions.
- **Status: fixed (A).**
- Containers are now named by content, with a `has_kind` edge to their Python type: a deliberate API change, pinned by tests.

**Relations:**
- They were held weakly, so a Kind reachable only by a relation could vanish.
- Their order was random.
- **Status: fixed (A):** strong references, ordered.

**Docs that described a different API:**
- Methods that do not exist: `que()`, `relate_to()`, `KindAdapter`, `from_int`… `from_enum`, `apply_mixin`, `Kind.prev()`.
- `kind.builtins` where the package is `kind.builtin`.
- A "length cache".
- `slim()` calling `gc.collect()`.
- The global freeze.
- `s` where it is now `k`.
- Python 3.8 where 3.10 is required.
- A README example whose shown output was not what it printed.
- **Status: fixed (C).**
- `Timeline.overlap()` was documented and missing: implemented **(A)**.

**Dead or unreachable code:**
- `red_black_tree.py` (used only by its own test).
- `kindable.py`, `utils/memory.py`, `type_var_t.py`, `lazy.py`.
- `config.py`: it could never be constructed and had no consumer.
- **Status: fixed (A)**, removed.

**Identity guard:** `elevate()` would have written `metadata['name']` (or `children`, …) onto the slot, renaming a Kind without updating the pool and so breaking its identity. **Status: fixed (A):** identity and structure slots are refused with a warning; `origin` and `node_shape` may still be elevated.

**Naming:**
- `has_type` in the README example → `has_kind`.
- `type_var_t.py` inlined.
- **Status: fixed (A/C).**
- The `filter_by_*` methods that return aggregates (`filter_by_average`, `filter_by_count`, …) are misnamed: **open**. Recommendation: rename them to `average_by(fn)` etc. or move them to a separate statistics view.

## (d) Tests

**Structure:**
- One autouse fixture resets the pool, the creation order and the mixin registry. It replaces per-file swaps that did not reach `Kind`'s separate pool.
- Every anyio test runs on asyncio and trio. The old `--ignore=path::id` options matched nothing.
- `filterwarnings = error`, which found an unclosed file and a deprecated pytest API.

**Removed as meaningless:**
- the 9 `.feature` files (never executed; they mirrored the pytest tests);
- duplicated blocks in two files, and one whole duplicate file;
- an empty test file;
- a test nested inside another test, which never ran;
- `test_imports`, which passed vacuously: it is now a strict xfail, measured in a fresh interpreter.

**Rewritten:**
- The scheduler tests run on a fake clock through `run_due_jobs()`; one real-time test of `start()` remains.
- The three serialization files became one parametrized file with an independent oracle.
- The conversions became a table.
- Tests that asserted log text now assert behaviour.

**Added:**
- security regressions;
- deep and cyclic graphs;
- traversal modes;
- relations and inverses;
- per-instance freeze;
- the creation-order API;
- the CLI through `CliRunner`;
- Graphviz output (`dot` is now detected instead of skipped unconditionally);
- the scenarios from the Gherkin files that pytest lacked (time views, period properties);
- the examples on `kind_vs_type.md`, executed as tests.

**Open:**
- `_parse_timestamp` silently maps an unparseable name to today at midnight, and the tests pin that. Recommendation: return `None` or raise, and let the time views skip non-temporal Kinds.
- `docs/development/directory_validation_lr.mmd` and `_tb.mmd` describe a "Directory Validation System" (DirectoryOverlapValidator, ClipboardMonitor) unrelated to `kind`: probably from another project. They are left in place for the author to decide.
- `Kind.len()` walks the creation-order tree: O(n). A counter would need to follow GC collections too.
- `deep_del` (in `maturing.py`) is tested but not called by the library.
- `Kind.from_object(dict)` hangs each value under its key, and keys are interned, so `Kind('a')` gathers the values of every converted dict that has the key `'a'`. This follows from interning and is documented in `conversion_to_and_from.md`. If per-dict isolation is wanted, the key edge would need a dict-scoped name.
- The two strict xfails document the planned lazy builtin loading (`kind/__init__.py`), which is not implemented.
